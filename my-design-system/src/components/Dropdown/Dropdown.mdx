# Dropdown

Floating menu attached to any trigger (`Button`, an icon button, or an `Avatar`). Composed from `DropdownListItem`, `DropdownHeader` and `DropdownDivider`; closes on outside click, `Escape`, or item selection.

<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### ✅ When to use
- For a set of actions attached to a trigger — a "..." menu, a user/account menu, a per-row table action menu.
- For a multi-select filter with more options than comfortably fit as visible `Checkbox`es — use `checkbox` items.

### 🚫 When not to use
- To let the user pick a single value for a form field — use `InputDropdown`, which shows the current value as the trigger.
- For 2–6 always-visible mutually exclusive options — a `Radio` group is faster to scan.

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Trigger
- ✅ Any interactive element works as `trigger` — `Dropdown` clones it to inject `onClick`, `aria-haspopup` and `aria-expanded`, so a `Button`, a plain icon button, or an `Avatar` all work unmodified.
- 🚫 Don't pass a non-interactive element (plain text, an image) as `trigger` — it needs to accept `onClick` and receive focus.

### Menu content
- ✅ Group related actions with a `DropdownHeader`; separate destructive or unrelated actions with a `DropdownDivider`.
- ✅ Use `shortcut` only for actions that also have a real keyboard shortcut elsewhere in the app — don't invent one just to fill the slot.
- 🚫 Don't nest another `Dropdown` inside a menu item — for hierarchical actions, prefer a second, separately-triggered menu.

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Roles:** the menu container renders `role="menu"`; items render `role="menuitem"` (or `role="menuitemcheckbox"` with `aria-checked` when `checkbox` is set).
- **Trigger semantics:** `aria-haspopup="menu"` and `aria-expanded` are set automatically on the cloned trigger.
- **Dismissal:** `Escape` and clicking outside both close the menu; focus is never trapped, so `Tab` continues past the trigger normally once closed.
- **Disabled items:** always use the native `disabled` attribute, which removes the row from tab order and communicates the state to screen readers.
