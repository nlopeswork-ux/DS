<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### ✅ When to use
- To let the user pick exactly one option among 2–6 mutually exclusive, always-visible choices.
- When every option should be scannable at a glance, with no extra click to reveal them (unlike a `Dropdown`).

### 🚫 When not to use
- To select more than one option — use `Checkbox`.
- For more than ~6 options, or when options are long/dynamic — use a `Dropdown` instead, to avoid an overwhelming list.
- To toggle a single setting on/off — use `Toggle`.

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Grouping
- ✅ All radios in the same group **must** share the same `name` — that's what makes the browser enforce single selection natively.
- ✅ Exactly one option should be selected by default whenever a neutral state doesn't make sense (e.g. a required plan choice).
- 🚫 Don't use a `Radio` group for a single yes/no choice — a `Checkbox` or `Toggle` communicates that more directly.

### Label & supporting text
- Same pattern as `Checkbox`: label is required, supporting text is optional and adds context that doesn't fit the label.

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Native semantics:** renders a native `<input type="radio">` — the browser handles single-selection and arrow-key navigation within a shared `name` group automatically.
- **Label association:** the label is linked via `htmlFor`/`id` (auto-generated with `useId` when no `id` is provided), so clicking the text also selects the control.
- **Visible focus:** the focus ring must never be disabled — it's the primary visual cue for keyboard navigation.
- **Disabled state:** always uses the native `disabled` attribute, which removes the control from tab order and communicates the state to screen readers.
