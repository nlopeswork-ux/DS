# Icon

The single, official icon set for the Design System, built on Google's [Material Symbols](https://fonts.google.com/icons) variable font. Every component that needs an icon — Button, Input, Dropdown, cards, navigation — renders it through this wrapper, never a static SVG or emoji.

<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### ✅ When to use
- Any place the system needs a pictogram — inside a Button, an Input's leading/trailing slot, a card, a nav item, a status badge.
- To reinforce or replace a text label when space is limited, as long as the meaning stays recoverable (see [Accessibility](#accessibility)).
- Consistently across the whole product — one icon set, one visual language.

### 🚫 When not to use
- Never use raw emoji (🎨, ✅, 🔥…) as UI icons — inconsistent rendering across OS/browsers and no control over weight or optical size.
- Never hand-draw a one-off SVG for something Material Symbols already covers — check [fonts.google.com/icons](https://fonts.google.com/icons) first.
- Don't rely on an icon alone to communicate a critical action with no text label or `label` prop nearby — see [Accessibility](#accessibility).

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Sizing
- `Icon` renders the glyph at a box size matched 1:1 to its font-size (`xs`=16px, `sm`=20px, `md`=24px, `lg`=28px, `xl`=32px) and drives the font's `opsz` (optical size) axis to the nearest supported stop, so strokes stay crisp instead of just scaling up a 24px design.
- Match the icon size to the text it sits next to — `sm`/`md` inside buttons and inputs, `lg`/`xl` for standalone or decorative use (empty states, feature cards).

<Canvas of={IconStories.Sizes} withToolbar={false} sourceState="none" />

### Filled vs. Outlined
- **Outlined** (default, `filled={false}`) is the resting state for most UI icons — lighter visual weight, consistent with the outlined strokes used elsewhere in the system (see `Checkbox`).
- **Filled** (`filled`) communicates an active/selected/toggled state — a filled heart after "favorite", a filled star after "rate" — the same role `:checked` plays on a Checkbox.

<Canvas of={IconStories.FilledVsOutlined} withToolbar={false} sourceState="none" />

### Color
- By default the icon inherits `currentColor` from its surrounding text — no `color` needed inside a Button or a label, it already matches.
- To assign a specific semantic meaning, pass one of the `fg-*` utility classes (`fg-success`, `fg-error`, `fg-warning`, `fg-brand-primary`, etc. — see `foundations/colors.md`) via `className`, or a raw CSS value via the `color` prop for one-off cases.

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Decorative by default:** with no `label`, `Icon` renders `aria-hidden="true"` — this is correct whenever the icon sits next to visible text that already carries the meaning (e.g. inside a Button).
- **Meaningful icons need a `label`:** when an icon is the *only* content conveying meaning (an icon-only button, a status glyph with no adjacent text), pass `label` — it switches the icon to `role="img"` + `aria-label`, exposing it to screen readers.
- **Never encode meaning by color alone:** a filled red icon should be paired with a text state (e.g. "Error") somewhere nearby — color reinforces, it doesn't replace, the accessible label.
- **Font loading:** the Material Symbols stylesheet is loaded once, globally (`.storybook/preview-head.html` for Storybook, `index.html` for the app) — components never load their own copy of the font.
