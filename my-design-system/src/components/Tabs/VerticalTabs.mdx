{/* Example gallery in tabs — replaces several stacked <Canvas> blocks with a single navigable widget. */}
export const ExampleGallery = ({ tabs }) => {
  const [active, setActive] = useState(0);
  return (
    <div className="my-6 rounded-lg border border-secondary overflow-hidden">
      <div role="tablist" className="flex gap-1 border-b border-secondary bg-secondary px-2 pt-2">
        {tabs.map((tab, i) => (
          <button
            key={tab.label}
            type="button"
            role="tab"
            aria-selected={i === active}
            onClick={() => setActive(i)}
            className={cn(
              'rounded-t-md border border-b-0 border-transparent px-4 py-2 -mb-px text-sm font-semibold',
              i === active ? 'bg-primary text-primary border-secondary' : 'text-tertiary hover:text-secondary',
            )}
          >
            {tab.label}
          </button>
        ))}
      </div>
      <div className="relative isolate bg-primary p-6">{tabs[active].content}</div>
    </div>
  );
};

# Vertical Tabs

Vertical tabs stack the sections in a column beside the content — a good fit for settings pages with many sections. Three types (**Button primary**, **Line**, **Button border**) in two sizes. On mobile the list becomes a dropdown and the panel moves below. For a row of tabs above the content use [Tabs](?path=/docs/components-tabs--docs).

<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### When to use
- Settings or profile areas with many (5–12) sections and short labels.
- Layouts with room for a side column, where the content is wider than tall.

### Types
- **Button primary** — pill tabs; the current one has a brand tint.
- **Line** — a 2px brand line on the left of the current tab.
- **Button border** — tabs sit in a bordered, tinted track; the current one is a white raised chip.

### When not to use
- Only a few sections — horizontal [Tabs](?path=/docs/components-tabs--docs) are lighter.
- Navigation across pages of an app — use the navigation components.

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Structure
- **Tab** — left-aligned label with an optional count badge after it.
- **List** — a column with `gap-xs`; in Button border it sits in a bordered, tinted track.
- **Sizes** — `sm`: 14px labels, 36px tabs. `md`: 16px labels, 44px tabs (the Button border track uses `p-sm` and `rounded-xl`).
- **Panel** — rendered beside the list, filling the remaining width.

### Best practices
- Keep labels short and parallel; the list is as wide as its longest label.
- Keep the current tab in the URL or in state the parent owns (`value` + `onValueChange`).

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Semantics:** `role="tablist"` / `role="tab"` / `role="tabpanel"`, with `aria-selected`, `aria-controls` and `aria-labelledby` wiring each tab to its panel. Give the list an `aria-label`.
- **Keyboard:** only the current tab is in the Tab order (roving tabindex). ↑ ↓ move between tabs — selection follows focus — and Home / End jump to the first / last tab.
- **Mobile:** below 640px the list is replaced by a dropdown (a combobox) with the same options.
- **Not only color:** the current tab also changes weight context via its fill, underline or line, not hue alone; the badge is plain text.
