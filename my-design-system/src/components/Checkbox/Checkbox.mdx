# Checkbox

Binary or multi-select control for forms and lists. Supports an independent mixed/indeterminate visual state for "select all" patterns, with full Light/Dark Mode support and 2 sizes.

<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### ✅ When to use
- To let the user select one or more independent options from a set (e.g. a list of settings, a multi-select filter).
- For a single binary agreement (e.g. "Accept terms and conditions").
- As a "select all" control at the top of a list, using the `Indeterminate` state when only some children are selected.

### 🚫 When not to use
- To pick exactly one option among several mutually exclusive choices — use `Radio`.
- To toggle a setting that takes effect immediately, with no explicit form submission — use `Toggle`.

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Label & supporting text
- ✅ Label describes the option being selected, in sentence case, without a trailing colon.
- ✅ Supporting text adds context that doesn't fit in the label (e.g. legal detail, consequence of the choice) — optional, omit when the label is self-explanatory.
- 🚫 Don't rely on the checkbox alone to convey meaning — every checkbox needs a visible label (or an explicit `aria-label` when the label is rendered elsewhere).

### Indeterminate
- Use only on a parent/"select all" checkbox whose children are partially selected — never as a resting/default state for a standalone checkbox.
- The `indeterminate` prop is purely visual (and exposed to assistive tech via the native DOM `indeterminate` property); the underlying `checked` value is unaffected and still drives what happens on the next click.

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Native semantics:** renders a native `<input type="checkbox">` — reachable with `Tab`, toggled with `Space`, with no need for extra `role` or key handling.
- **Label association:** the label is linked via `htmlFor`/`id` (auto-generated with `useId` when no `id` is provided), so clicking the text also toggles the control.
- **Indeterminate:** set through the DOM `indeterminate` property (not an HTML attribute), which browsers and screen readers automatically expose as a mixed state — no manual `aria-checked` needed.
- **Visible focus:** the focus ring must never be disabled — it's the primary visual cue for keyboard navigation.
- **Disabled state:** always uses the native `disabled` attribute, which removes the control from tab order and communicates the state to screen readers.
