<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### ✅ When to use
- To collect a single line of free-form text — name, email, password, search term, amount.
- With `leadingDropdown`/`trailingDropdown` when the value has an inherent unit or prefix the user must also choose (phone country code, currency).
- With `trailingButton` for a paired action on the field's own value (copy a link, regenerate a code).

### 🚫 When not to use
- For multi-line content — use `Textarea`.
- For a fixed set of options with no free text — use `Dropdown` or `InputDropdown`.
- For a short, fixed-length code (OTP/2FA) — use `VerificationCodeInput`, which is easier to scan and paste into.

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Label & hint
- ✅ Label is always visible above the field — never rely on a placeholder alone as the label (it disappears once the user types).
- ✅ Hint text gives format guidance ("Minimum 8 characters") and disappears automatically once an error message takes its place.
- 🚫 Don't show both hint and error message at once — the component already hides the hint whenever `destructive` + `errorMessage` are set.

### Type-specific slots
- `iconSwap`, `leadingTextAddon`, `paymentIcon` and the `tags` chips all share the field's own padding — no separate background, they read as part of the same input.
- `leadingDropdown`, `trailingDropdown` and `trailingButton` instead span the full field height, edge to edge, with their own fused background/border.
- `helpIcon` (an info icon, swapped for an alert icon when `destructive`) only renders when the trailing slot is free — it's automatically suppressed for `trailingDropdown`, `trailingButton` and `tags`.
- Always give `leadingDropdown`/`trailingDropdown` an `ariaLabel` (e.g. "Country code"), since the fused select has no visible label of its own.

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Label association:** the label is linked via `htmlFor`/`id` (auto-generated with `useId` when no `id` is provided).
- **Error announcement:** `aria-invalid` and `aria-describedby` point to the error message so screen readers announce it as part of the field.
- **Visible focus:** the focus ring must never be disabled — it's the primary visual cue for keyboard navigation, and it also engages for the fused leading/trailing dropdown or button.
- **Dropdown segments:** always pass `ariaLabel` on `leadingDropdown`/`trailingDropdown` — they're native `<select>` elements with no visible label of their own.
- **Tag removal:** every chip's remove button has an explicit `aria-label` ("Remove design-system") — never rely on the "×" glyph alone.
- **Disabled state:** always uses the native `disabled` attribute on the input and any dropdown/button segment, which removes them from tab order and communicates the state to screen readers.
