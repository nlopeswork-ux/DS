<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### ✅ When to use
- To reveal a short explanation for an icon, truncated label or unfamiliar control on hover/focus.
- Alongside a `HelpIcon` to give optional, non-critical context without cluttering the layout.
- To confirm what an icon-only action does before the user commits to it.

### 🚫 When not to use
- For information required to complete a task — tooltips are easy to miss (no keyboard-only discovery without a focusable trigger) and disappear on blur; put essential content inline instead.
- On touch-only interfaces as the only way to reveal content — there's no hover state to trigger it.
- For long-form text — keep the title to a short phrase; use `supportingText` sparingly, for one extra sentence at most.

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Structure
- **Title (`text`)** — the tooltip's main message. Keep it to a short phrase ("Add user", "Copy link").
- **Supporting text (`supportingText`)** — an optional second line with extra context, shown below the title with a 4px gap.
- **Arrow (`arrow`)** — a pointer triangle on the box edge closest to the trigger element (`'None'` to omit it, e.g. inside a wider overlay).

### Best practices
- ✅ Position the tooltip so its arrow always points back at the element that triggered it.
- ✅ Pair with a real interactive/focusable trigger (see `HelpIcon`) so keyboard users can reach it too.
- 🚫 Don't rely on a tooltip for content that changes the outcome of a task — treat it as supplementary only.

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Role:** rendered with `role="tooltip"` by default, so assistive technology announces it as a tooltip when linked via `aria-describedby` from its trigger.
- **Keyboard discovery:** the Tooltip itself doesn't manage focus — always attach it to a real focusable trigger (button, link) so `:focus-visible` can reveal it, not just `:hover`. See `HelpIcon` for the reference pattern.
- **Contrast:** `text-white` on `bg-primary-solid` and `text-tooltip-supporting` on `bg-primary-solid` both meet WCAG AA for small text in both color themes.
