export const ExampleGallery = ({ tabs }) => {
  const [active, setActive] = useState(0);
  return (
    <div className="my-6 rounded-lg border border-secondary overflow-hidden">
      <div role="tablist" className="flex gap-1 border-b border-secondary bg-secondary px-2 pt-2">
        {tabs.map((tab, i) => (
          <button
            key={tab.label}
            type="button"
            role="tab"
            aria-selected={i === active}
            onClick={() => setActive(i)}
            className={cn(
              'rounded-t-md border border-b-0 border-transparent px-4 py-2 -mb-px text-sm font-semibold',
              i === active ? 'bg-primary text-primary border-secondary' : 'text-tertiary hover:text-secondary',
            )}
          >
            {tab.label}
          </button>
        ))}
      </div>
      <div className="relative isolate bg-primary p-6">{tabs[active].content}</div>
    </div>
  );
};

# Input Dropdown

Select-style form field — shows the current value as its trigger, opens a listbox of `_Input dropdown menu item`s on click. Optional type-ahead search. Full keyboard navigation (Arrow keys, Enter, Escape).

<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### ✅ When to use
- To let the user pick exactly one value for a form field, from a list too long or too dynamic for `Radio`.
- With `searchable` when the option list exceeds ~10 items.
- With a `dotColor` per option for status-style fields (To do / In progress / Done).

### 🚫 When not to use
- For a set of triggered actions (not a form value) — use `Dropdown`.
- For 2–6 always-visible options — a `Radio` group is faster to scan and needs no click to reveal choices.

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Options
- ✅ Give every option a stable `value` (an id, a slug) — never rely on `label` as the value, since labels can change independently.
- ✅ Combine at most one leading decoration per option — `icon`, `avatar`, or `dotColor` — mixing more than one crowds the row.
- 🚫 Don't disable more than a couple of options — if most of the list is unavailable, reconsider whether it should be in the list at all.

### Search
- Filters on `option.label` only, case-insensitive substring match — for a large or remote dataset, filter the `options` array yourself and keep this component's own `searchable` off.

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Combobox pattern:** the trigger renders `role="combobox"` with `aria-haspopup="listbox"`, `aria-expanded` and `aria-controls`; the menu renders `role="listbox"` with `role="option"`/`aria-selected` rows.
- **Keyboard:** `Enter`/`Space`/`ArrowDown` open the field; once open, `ArrowUp`/`ArrowDown` move the highlighted option, `Enter` selects it, `Escape` closes without changing the value.
- **Label association:** the label is linked via `htmlFor`/`id` (auto-generated with `useId` when no `id` is provided).
- **Disabled options:** rendered with `aria-disabled` and excluded from selection, but still visible for context (e.g. "Viewer — requires upgrade").
- **Dismissal:** clicking outside closes the menu without discarding the previously selected value.
