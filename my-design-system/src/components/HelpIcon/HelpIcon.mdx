export const ExampleGallery = ({ tabs }) => {
  const [active, setActive] = useState(0);
  return (
    <div className="my-6 rounded-lg border border-secondary overflow-hidden">
      <div role="tablist" className="flex gap-1 border-b border-secondary bg-secondary px-2 pt-2">
        {tabs.map((tab, i) => (
          <button
            key={tab.label}
            type="button"
            role="tab"
            aria-selected={i === active}
            onClick={() => setActive(i)}
            className={cn(
              'rounded-t-md border border-b-0 border-transparent px-4 py-2 -mb-px text-sm font-semibold',
              i === active ? 'bg-primary text-primary border-secondary' : 'text-tertiary hover:text-secondary',
            )}
          >
            {tab.label}
          </button>
        ))}
      </div>
      <div className="relative isolate bg-primary p-6">{tabs[active].content}</div>
    </div>
  );
};

<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### ✅ When to use
- Next to a form field label or a dense data-table column header, to explain a term without permanently taking up layout space.
- Anywhere the same information would otherwise need a permanently-visible caption.

### 🚫 When not to use
- For content the user must read to complete the task — hover-revealed content is easy to miss.
- As a replacement for real inline help text or a `supportingText` under a field — reserve it for genuinely optional context.

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Structure
- **Icon** — a 16×16 `help` glyph, always visible.
- **Tooltip** — an internal [`Tooltip`](?path=/docs/components-tooltip--docs) instance, shown on hover/focus (or forced via `open`).
- **Cursor (`cursor`)** — a decorative pointer glyph shown alongside the open tooltip, mirroring the original hover-state prototype. Purely visual — hide it (`cursor={false}`) in touch/keyboard-first contexts where no real pointer is present.

### Best practices
- ✅ Always let `tooltipArrow` point back toward the icon that triggered it — the position mapping already does this for you.
- ✅ Keep `tooltipText` to a single short sentence; reach for `supportingText` only when one extra sentence of context is truly needed.
- 🚫 Don't use `open` in production UI to keep a tooltip permanently visible — it exists for docs/demos and controlled edge cases, not as a substitute for real hover/focus behavior.

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Focusable trigger:** the icon renders as a native `<button aria-label="More information">`, reachable with `Tab` — the tooltip opens on `:focus-visible`, not just `:hover`, so keyboard users can reach it too.
- **Association:** the tooltip is linked back to the trigger via `aria-describedby`, so screen readers announce it as part of the button's description.
- **Decorative cursor:** the `cursor` glyph is marked `aria-hidden` — it carries no meaning of its own.
