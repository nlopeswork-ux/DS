<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### ✅ When to use
- To pair a short highlighted value ("New", "Beta", "+3") with plain-language context — release notes, changelogs, notification summaries.
- Wherever a standalone [Badge](?path=/docs/components-badge--docs) would read as too terse on its own and needs a sentence of support right next to it.

### 🚫 When not to use
- For a single label with no supporting text — use a plain `Badge` instead.
- As an interactive control — like `Badge`, `Badge group` has no built-in click behavior; wrap it in a `Button`/link if the whole pill needs to be actionable.

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Structure
- **Badge chip** (`badge="Leading"`/`"Trailing"`) — a compact `Badge color` rendered inside the group, carrying the short highlighted value (`badgeLabel`). Optionally shows a `Dot` indicator (`icon` boolean).
- **Descriptive text** (`children`) — plain-language context next to the chip, in the group's own color.

### Best practices
- ✅ Keep the Badge chip text very short (1 word, e.g. "New") — the surrounding text carries the detail.
- ✅ Use `badge="Leading"` (the default) for "label first" reading order ("New — 3 unread messages"); reserve `"Trailing"` for cases where the description reads more naturally first ("3 unread messages — New").
- 🚫 Don't nest another interactive element (a button, a link) inside the group — it isn't built to host focusable children.

See every theme/color/position combination in the tab gallery under [UX Guidelines](#ux-guidelines).

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Contrast:** the same `utility-{color}-50/200/700` token triplet as `Badge` — every theme/color pair meets WCAG AA (ratio ≥ 4.5:1) for text.
- **Semantics:** renders as a plain `<span>` with visible text — no extra ARIA role needed since both the chip and the description are already text content read in order by screen readers.
- **Non-interactive:** `Badge group` carries no focusable element on its own; if it needs to be clickable as a whole, wrap it in a `Button`/link rather than adding click handlers directly to the `<span>`.
