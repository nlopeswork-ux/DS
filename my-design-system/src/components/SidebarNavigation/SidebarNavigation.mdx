            {tab.label}
          </button>
        ))}
      </div>
      <div className="relative isolate bg-primary p-6">{tabs[active].content}</div>
    </div>
  );
};

<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### When to use
- Applications with several top-level sections that users move between all day.
- **Simple** when sections have a few pages each and users benefit from seeing them in place.
- **Dual-tier** when sections have many pages — the second column keeps the whole list visible without nested accordions.
- **Slim** when the content needs the width: an icon-only rail that opens a second column for the current section.

### When not to use
- Marketing sites or pages with a handful of links — use a header navigation.
- For moving *within* a page or a flow — use Tabs or Breadcrumbs.

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Structure
- **Logo** — the 32px KDS mark and logotype (`logo` replaces it). Slim shows only the mark.
- **Search** — an `Input` with a leading search icon (`showSearch`).
- **Main items** — icon, label, optional badge or status dot. An item with `items` has a second level: it expands in place in Simple and on mobile, and fills the second column in Dual-tier and Slim. Picking a parent lands on its first enabled child, so the second column always has a current page.
- **Footer items** — Support, Settings and similar, pinned to the bottom.
- **Featured card** — a usage or promo card above the account: `Progress bar` in Simple, `Progress circle` in Dual-tier. It has Dismiss and an action, plus a close button.
- **Account** — avatar, name, email and a log-out button. Pass `avatarSrc` for a photo (the stories use free dummy portraits from `public/avatars/`); without one the initials are shown.
- **Widths** — Simple 312px, Dual-tier 280px (528px with the second column), Slim 80px (362px open). From 1024px (`lg`) it is the full sidebar; below, a 64px top bar whose menu button opens a 311px drawer beside a dimmed scrim.

### Best practices
- Keep the main list to about seven items; move the rest to the second level.
- Labels are short nouns that match the page titles. Use a badge only for counts that need attention.
- The sidebar fills its parent's height — give it a container with a height (`h-screen`, a grid row) and let it scroll internally.
- Control the selection with `value` / `onValueChange` when it follows the router; items with `href` render links.

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Landmarks:** the sidebar is an `aside` labelled "Main navigation" (override with `aria-label`) containing a `nav` for the main items, one for the footer items and one for the second column (named after its section, e.g. "Dashboard pages").
- **Current page:** `aria-current="page"` on the current link or button.
- **Expandable items:** parents are buttons with `aria-expanded` and `aria-controls` pointing at their list.
- **Icon-only items (Slim):** carry the label as `aria-label` and `title`.
- **Mobile drawer:** the menu button has `aria-expanded` / `aria-controls`; the open drawer is a modal dialog that locks page scroll, traps focus and restores it to the menu button on close. Esc, the scrim and the close button all close it.
- **Keyboard:** every item is a native link or button — Tab to move, Enter / Space to activate — with a visible focus ring.
