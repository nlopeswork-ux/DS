# Alert

Communicates information, success, risk or failure without interrupting the workflow. Combines a semantic icon, a title, optional supporting text and an action group, in two presentations: **floating** (a delimited card) and **full-width** (a banner across the page or section). On mobile (< 640px) the full-width banner drops its icon and stacks its actions.

<h2 id="ux-guidelines" className="text-2xl font-semibold">UX Guidelines & When to Use</h2>

### When to use
- **Informative** — news, changes or contextual information that is not a failure. Actions: "View changes", "Learn more".
- **Success** — confirmation of a completed operation. Actions: view the profile or the result.
- **Warning** — risks, limitations or conditions that may cause a problem. Actions: review the configuration, update data.
- **Error** — an operation failed or a problem needs correcting. Actions: "Try again", "View details".
- **Floating** — a delimited area of the interface with a title, an explanation and actions.
- **Full-width** — a banner that spans the whole page or section.

### What to avoid
- Several alerts competing for attention without a clear priority.
- Using Warning for a failure that already happened — that is an Error.
- Treating "Dismiss" as "Resolve" or "Undo".

<h2 id="anatomy-best-practices" className="text-2xl font-semibold">Anatomy & Best Practices</h2>

### Structure
- **Featured icon** — a semantic glyph (info, check, alert) in the alert colour with two soft rings. Hidden on the mobile full-width banner.
- **Title** — short and descriptive, `text-sm` semibold.
- **Supporting text** — optional; may contain an inline link. Below the title in a floating alert, inline after it in a full-width banner.
- **Actions** — "Dismiss" plus one primary action, as link-style buttons. The informative full-width banner uses a secondary + primary button pair, stacked on mobile.
- **Close (X) button** — optional, top-right.

### Best practices
- Show the alert close to the context it affects. It is not a modal: it never blocks the page and never traps focus.
- Do not auto-hide alerts that contain essential actions.
- The close button and "Dismiss" only hide the message — they never undo an operation or solve the underlying problem.
- Use labels that describe the result ("Try again", "View changes"), and set `actionLoading` while an asynchronous action runs to prevent duplicate submissions.

<h2 id="accessibility" className="text-2xl font-semibold">Accessibility (a11y)</h2>
- **Semantics:** `role="alert"` for error and warning, `role="status"` for informative and success.
- **Not only color:** every alert pairs its color with a semantic icon and text.
- **Close button:** icon-only, with an `aria-label` (default "Dismiss alert").
- **Focus:** actions and the close button have a visible focus ring; the alert itself is never a focus trap.
- **Async actions:** the primary action is disabled and `aria-busy` while loading.

> Implementation note: the featured icon and close (X) button are internal placeholders until their own components exist.
